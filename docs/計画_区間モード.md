# 区間モード 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 地図で峠区間をなぞり、複数コーナーを通しで6本の走行ラインを物理モデルで比べる `section.html` を作る。既存の1コーナー比較 `index.html` は壊さない。

**Architecture:** 既存 `index.html` の DOM 非依存な物理計算を `js/physics.js` に切り出して両ページで共用。新規の `track.js`（地図座標→中心線・曲率・コーナー検出）、`lines.js`（ピン付き最小曲率ソルバー・型ライン・最速探索）、`map.js`（Leaflet・OSRM・幅計測）、`store.js`（区間の保存）、`section-ui.js`（画面）をビルド無しの `<script>` で読む。各 JS は末尾に `if (typeof module !== 'undefined') module.exports = {...}` を持ち、Node からもテストできる。

**Tech Stack:** 素の JS（ES2020）、Leaflet 1.9（CDN: cdnjs）、OpenStreetMap タイル、国土地理院 航空写真タイル、OSRM 公開サーバー、Overpass API、Node 24 `node --test`

**Spec:** `docs/仕様.md`

## Global Constraints

- 回答・コード内コメント・コミットメッセージは日本語。コミットは日本語 Conventional Commits（例: `feat: 区間モードの地図を追加`）
- ビルド工程を持たない。外部 JS は CDN（cdnjs.cloudflare.com）から読む。有料サービス・API キーは使わない
- 既存 `index.html` の計算結果は変えない（回帰テストで15個のタイムが誤差 0.001 秒以内）
- 中心線の刻み `ds = 1.0 m`。曲率の平滑化は移動平均 ±5 m。コーナー判定 |κ| > 1/150、連続 8 m 以上、同方向 15 m 未満の間隔はまとめる
- 走行範囲の余白 1.0 m。横位置 n は進行方向**右を正**（既存の規約）。全幅: `[-(W/2-1), W/2-1]`、自車線: `[-(W/2-1), 0]`
- 幅 W: 既定 6.0、範囲 3〜12、刻み 0.1。進入速度 既定 60 km/h、範囲 20〜150。区間長 100〜5000 m
- 最速探索: 位置 `[0.30,0.40,0.50,0.55,0.60,0.70,0.80]` × 寄せ `[1.0,0.7,0.4]` × 保持 `[0,10,20]` m を各コーナーで試し、全コーナー2周
- レイトエイペックス: 位置 0.65・寄せ 1.0・保持 10 m
- localStorage キー: 区間一覧 `section-sim-v1`、地図の表示位置 `section-sim-view-v1`
- OSRM: `https://router.project-osrm.org/route/v1/driving/{lng,lat;...}?overview=full&geometries=geojson`。Overpass: `https://overpass-api.de/api/interpreter`

## Review Focus

1. OSRM が同じ座標を連続で返す／極端に短い辺を返す → `resample` が長さ0の辺を飛ばし、NaN を出さない（Task 2 にテスト）
2. 峠のヘアピン（R=8 m・180°）→ 曲率が ds=1 m で破綻せず、コーナーとして1つに検出される（Task 3 にテスト）
3. 自車線モード × W=3 m → 範囲 `[-0.5, 0]` でもソルバーが収束し、範囲内に収まる（Task 4 にテスト）
4. コーナーが区間の先頭／末尾に接している（i0=0 または i1=N-1）→ ピンが配列外にならない（Task 5 にテスト）
5. 5 km 離れた点の平面座標変換 → 緯度経度へ戻したとき誤差 0.5 m 未満（Task 2 にテスト）

**Interfaces:**
